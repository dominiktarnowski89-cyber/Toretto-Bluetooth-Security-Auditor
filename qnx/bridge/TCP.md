# TCP transport (QNX 8)
Alternative to the lossy UART prototype. The native analyzer accepts one TCP session with --tcp (port 8765); each valid BLE window returns its native JSON summary on the same connection. Use an isolated QEMU user network with restrict=on and hostfwd=tcp:127.0.0.1:18765-10.0.2.15:8765, and virtio-net-pci. In the licensed guest start io-sock with vtnet_pci, wait for vtnet0, assign 10.0.2.15/24, and launch the analyzer with --tcp. Do not expose the unauthenticated guest service publicly.
Host: python3 qnx/bridge/tcp_bridge.py < qnx/contest/fixtures/rotation.ndjson
Verified 2026-11-24 in QNX 8 x86-64 on Netcup: valid records of 116, 2165, 65652, 1048692 and 4193396 bytes produced five sequential native results. An oversized 4194322-byte record was rejected with the exact byte count; the following valid record produced result six. ARM64 cross-compilation passed; runtime untested. This is a single-session prototype, not automatic reconnect or durable replay. The old UART remains unreliable. Existing serial demo scripts are unchanged.
